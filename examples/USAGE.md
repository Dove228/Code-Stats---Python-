## 快速开始

### 方法 1：运行exe（推荐）

1. 双击 `CodeStats.exe`
2. 选择功能（按数字键1-7）
3. 输入或拖拽文件夹路径
4. 查看统计结果

### 方法 2：命令行运行

```bash
# 进入项目目录
cd d:\Project\01

# 运行
python -m code_stats
```

## 交互模式

### 主菜单操作流程

```
1. 运行程序
   ↓
2. 显示主菜单
   ↓
3. 选择功能（按1-7）
   ↓
4. 输入文件夹路径
```

| `1` | 快速统计 | 基础统计信息 |

| `0` | 退出 | 关闭程序 |

## 命令行模式

### 基本语法

```bash
CodeStats.exe [路径] [选项]
```

### 常用命令

```bash
# 统计当前目录
CodeStats.exe .

# 统计指定目录
CodeStats.exe C:\path\to\project

# 详细模式
CodeStats.exe . -v

# 排除目录
CodeStats.exe . -e node_modules,__pycache__

# 只统计特定语言
CodeStats.exe . --lang python,javascript

# 导出报告
CodeStats.exe . -o report.json
```

### 选项说明

| 选项 | 说明 |
|------|------|
| `路径` | 要统计的目录或文件 |
| `-v, --verbose` | 显示详细信息 |
| `-e, --exclude` | 排除的目录（逗号分隔）|
| `--lang` | 只统计指定语言 |
| `-o, --output` | 输出文件路径 |
| `-f, --format` | 输出格式: json/csv/md |
| `--complexity` | 显示复杂度分析 |
| `--git` | 显示Git统计 |
| `--visualize` | 显示可视化图表 |

## 功能详解

### 1. 快速统计

适合快速了解项目概况。

**输出内容：**
- 总文件数
- 总行数/代码行/注释行/空行
- 代码占比
- 文件总大小
- 按语言统计

**使用场景：**
- 快速了解项目规模
- 日常代码统计

### 2. 详细统计

包含所有基础统计 + 文件详情。

**额外输出：**
- Top 20 代码文件列表
- 每个文件的代码行数

**使用场景：**
- 分析代码分布
- 找出代码量最大的文件

### 3. 复杂度分析

评估代码复杂度和结构。

**输出内容：**
- 圈复杂度（CC）
- 函数数量
- 类数量
- 最大复杂度
- 平均复杂度

**复杂度指标说明：**
- CC 1-10：简单，清晰
- CC 11-20：中等，需要注意
- CC 21-50：复杂，建议重构
- CC > 50：难以维护

**使用场景：**
- 代码审查
- 重构优先级评估

### 4. Git统计

显示Git仓库相关信息。

**输出内容：**
- 当前分支
- 远程仓库地址
- 贡献者列表
- 每人提交数、添加/删除行数

**要求：**
- 必须在Git仓库目录下运行

**使用场景：**
- 项目贡献分析
- 代码历史追踪

### 5. 可视化图表

ASCII图形化展示统计结果。

**图表类型：**
- 语言分布条形图
- 目录分布条形图
- 百分比显示

**使用场景：**
- 直观展示项目结构
- 报告演示

### 6. 导出报告

将统计结果保存为文件。

**支持格式：**
- **JSON**：完整数据，程序友好
- **CSV**：表格数据，Excel可用
- **Markdown**：美观报告，文档可用

**使用示例：**
```bash
CodeStats.exe . -o report.json
CodeStats.exe . -o report.csv
CodeStats.exe . -o report.md
```

### 7. 完整分析

一次运行包含所有功能。

**包含：**
- 详细统计
- 复杂度分析
- Git统计（如果在Git仓库中）
- 可视化图表
- JSON报告导出

**使用场景：**
- 项目全面评估
- 生成综合报告

## 使用示例

### 示例 1：日常统计

```
1. 运行 CodeStats.exe
2. 按 1 选择"快速统计"
3. 输入或拖拽文件夹路径
4. 查看结果
5. 按Enter返回，0退出
```

### 示例 2：代码审查

```
1. 运行 CodeStats.exe
2. 按 3 选择"复杂度分析"
3. 输入项目路径
4. 重点关注CC > 20的文件
5. 标记需要重构的代码
```

### 示例 3：生成报告

```
1. 运行 CodeStats.exe
2. 按 6 选择"导出报告"
3. 输入项目路径
4. 选择格式（1-JSON, 2-CSV, 3-Markdown）
5. 确认保存路径
6. 在指定位置查看报告文件
```

### 示例 4：Git项目分析

```
1. 进入Git仓库目录
2. 运行 CodeStats.exe
3. 按 4 选择"Git统计"
4. 查看贡献者统计
5. 分析团队贡献情况
```

### 示例 5：完整项目评估

```
1. 运行 CodeStats.exe
2. 按 7 选择"完整分析"
3. 输入项目路径
4. 一次性获取所有统计信息
5. 查看综合报告
```

## 技巧和最佳实践

### 提高效率

1. **记住常用功能**
   - `1` = 快速统计
   - `6` = 导出报告

2. **使用排除选项**
   ```
   排除目录: node_modules,__pycache__,venv,build
   ```

3. **语言过滤**
   ```
   语言: python,javascript,html,css
   ```

### 数据分析

1. **找重点文件**
   - 使用"详细统计"
   - 关注Top 20文件

2. **评估复杂度**
   - 使用"复杂度分析"
   - 优先处理CC > 20的文件

3. **团队协作**
   - 使用"Git统计"
   - 了解贡献分布

### 报告生成

1. **Markdown报告**
   - 用于文档
   - GitHub READMEs

2. **CSV报告**
   - 用于数据分析
   - Excel进一步处理

3. **JSON报告**
   - 用于程序处理
   - CI/CD集成

## 故障排除

### 问题1：程序无响应

**解决方法：**
- 等待扫描完成（大项目需要时间）
- 检查路径是否正确
- 确保有读取权限

### 问题2：统计结果为空

**可能原因：**
- 路径不存在
- 所有文件都被排除
- 目录为空

**解决方法：**
- 确认路径正确
- 检查排除设置
- 尝试统计父目录

### 问题3：Git统计不可用

**原因：**
- 不在Git仓库中
- 没有.git目录

**解决方法：**
- 进入Git仓库目录
- 或使用其他统计功能

### 问题4：导出失败

**可能原因：**
- 路径不存在
- 权限不足
- 磁盘空间不足

**解决方法：**
- 使用有效的路径
- 以管理员身份运行
- 清理磁盘空间
